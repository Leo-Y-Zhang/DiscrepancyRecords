# Incident: the campaign scratch tree was deleted, 2026-08-24 ~02:05

A recursive force-delete was run against two clone directories as a routine
"idle clone cleanup". One of them held a **live** campaign. It removed
everything without an open handle and reported only the four files that had one.
Free space went from 311.4 GB to 410.5 GB, which is the whole 99.1 GB of the
scratch tree. The force flag bypasses the Recycle Bin.

This file is the record. It is committed because the original lived in exactly
one place on one disk, which is the same mistake that caused the loss.

## Destroyed

- `scratch/wave274tot/` - **16,384 verdicts**, **1,383 proofs (91.2 GB)**,
  `transcripts.jsonl` (1,612 rows), `sample.json`, `base.cnf`, `cubes.txt`,
  `manifest.json`, `pruned.jsonl`, `CHECKER_ERRORS.jsonl`
- `scratch/wave274/` - 109 seqcount verdicts, `base.cnf`, `cubes.txt`,
  `manifest.json`
- Every scratch module: `cube_wave2.py`, `sample_prune.py`, `check_and_prune.py`,
  `verdict_io.py`, `watchdog.py`, `detach.py`, `campaign_state.py`,
  `console_immunity.py`, `crash_cleanup.py`, `resume_campaign.ps1`, and the tests
- The clone's `.git` directory
- A second clone entirely (clean and on origin, so nothing was lost with it)

## Survived, by open handle only

`scratch/campaign.log` (33,336 b), `scratch/pruneonly.log` (126,538 b),
`scratch/watchdog.log`, `scratch/watchdog_stdio.log`.

`campaign.log` still carries the phase-1 result verbatim:

```
[2026-08-23 01:02:54] totalizer-wave verdicts: UNSAT=16384 SAT=0 other=0
[2026-08-23 01:02:56] totalizer-final verdicts: UNSAT=16384 SAT=0 other=0
[2026-08-23 01:02:56] PHASE 1+2 COMPLETE: all 16384 totalizer cubes UNSAT
```

**A log line is not evidence.** This repository's standard is `verify_all.py`
exiting 0 over imported artifacts. The *finding* a(17)=274 stands; its
*evidence* had to be recomputed.

## No undelete path existed

Shadow copies and restore points both need administrator rights and this machine
has none. There is no File History, and the system volume is the only drive, so
the file-recovery tool could not be used - it requires a destination volume
different from the source. Recovery by carving was not available.

### Statistics measured from the data before it was lost

- totalizer, all 16,384 cubes: mean **277.4 s**, median 163.0 s,
  **1,262 core-hours total**
- totalizer, first 400 cubes: mean 61.4 s, median 15.2 s - the early cubes are
  cheap and the tail is heavy, which is why cube counts are a bad progress
  measure
- seqcount, the 109 solved: mean **448.8 s**, median 128.6 s, p90 1428.6 s,
  max 3519.4 s
- effective parallelism over a clean 6.33 h window: **15.95x** on 16 workers
  (1,271 verdicts, 101.0 core-hours). This is worker *utilisation*, not speedup
  over one core; the separate "4.7x versus a single core" figure measures a
  different thing and the two do not contradict each other.
- phase 3 at the moment of loss: **1,612 transcript rows** = 1,587 of the
  declared 1,600 plus 25 archive cubes (all ids congruent to 0 mod 512), **zero
  check failures, zero SAT**

## Root cause

The ignore file contained a single line excluding `scratch/`. That line meant
the entire pipeline - orchestrator, wave driver, pruner, checker, watchdog, the
durability fixes and their tests, six days of work - **had no backup anywhere**,
while `git status` reported the clone clean and `ls-remote` confirmed HEAD was
on origin. Both checks were true. Neither covered the code that mattered.

**A clean tree is not an empty directory.**

## What changed as a result

1. The pipeline source is tracked. Only the multi-gigabyte artifacts stay
   ignored, and the ignore rules were audited by asking what *evidence* they
   exclude rather than what bulk.
2. The trailing `*` in `scratch/wave*/*` is load-bearing: git cannot re-include
   a file whose parent directory is excluded, so `scratch/wave*/` plus
   negations looks correct and does nothing. The manifests and `sample.json`
   above were still untracked for most of a day because of exactly that.
3. Before any clone is proposed for deletion, its ignored and untracked content
   is sized and accounted for, not just its tracked state.
